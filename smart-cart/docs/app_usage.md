# SmartCart: инструкция пользователя

Эта инструкция описывает работу оператора с приложением SmartCart на тележке.

## Что нужно перед началом

1. Raspberry Pi включена.
2. Приложение SmartCart запущено.
3. Нужный модуль вставлен в тележку и определяется по RFID.
4. STM32 модуля подключена по UART.
5. На экране нет сообщения `Вставьте модуль`.

Если приложение показывает страницу `Вставьте модуль`, работать с заказом нельзя:
нужно физически установить модуль с RFID-меткой.

## Стартовая страница

Когда тележка свободна, на экране показывается:

```text
Остатков нет.
Тележка свободна. Выберите заказ.
```

На этом этапе оператор нажимает `Выбрать заказ` или `Загрузить заказ`.

## Загрузка заказа

Приложение поддерживает два формата:

```text
JSON заказа: *.json
BOM Excel:   *.xlsx, *.xls
```

Обычный сценарий для оператора:

1. Нажать `Загрузить заказ`.
2. Выбрать файл BOM Excel или JSON.
3. Если тележка пустая, выбрать `Тележка пустая`.
4. Если тележка уже была в работе и питатели уже лежат в ней, выбрать
   `Была в работе`.

Если выбран BOM Excel, приложение само:

1. читает колонку `PartNumber`;
2. считает количество компонентов;
3. назначает приоритеты `P1`, `P2`, `P3`;
4. создаёт внутренний заказ;
5. переводит тележку в рабочий маршрут.

Для BOM обязательна колонка:

```text
PartNumber
```

Если такой колонки нет, заказ не загрузится.

## Приоритеты компонентов

Приоритет показывает, насколько часто компонент используется в плате:

```text
P1: первые 50% общего количества компонентов
P2: следующие 35%
P3: оставшиеся 15%
```

В чек-листе заказа строка выглядит примерно так:

```text
P1 · R03015_0 ×25 → слот 3 [ожидает]
```

Это значит:

```text
P1          высокий производственный приоритет
R03015_0    PartNumber
×25         количество на плату
слот 3      куда положить материал
```

## Загрузка питателей

Если при выборе заказа оператор указал `Тележка пустая`, маршрут начинается с
этапа загрузки питателей.

Оператор:

1. нажимает `Загрузка питателей`;
2. физически загружает питатели в модуль питателей;
3. проверяет состояние модуля на экране;
4. нажимает `Питатели загружены`.

Если тележка была в работе, этот этап пропускается.

## Подбор материалов на складе

На этапе подбора материалов оператор берёт катушку со склада и сканирует её
штрихкод.

Штрихкод может содержать `PartNumber` внутри строки. Например:

```text
BOX-77|PN=R03015_1k|LOT=42
```

Если в заказе есть `PartNumber = R03015_1k`, приложение примет такой скан.

После успешного скана приложение подсказывает целевой слот. Оператор кладёт
катушку в нужный слот.

Если катушка положена в правильный слот:

```text
позиция становится размещённой
операция завершается успешно
слот становится занятым
```

Если катушка положена не в тот слот:

```text
позиция получает ошибку
слот помечается как проблемный
оператор должен исправить размещение
```

## Подготовка питателей

После завершения подбора приложение переводит тележку к подготовке питателей.

Оператор:

1. перевозит тележку в зону подготовки питателей;
2. нажимает `Прибыла к питателям`;
3. нажимает `Начать подготовку`;
4. выполняет подготовку;
5. нажимает `Питатели готовы`.

На этом этапе приложение показывает состояние модуля питателей.

## Выдача на линию

После подготовки питателей тележку нужно перевезти на линию SMT.

Оператор:

1. нажимает `Прибыла на линию`;
2. нажимает `Начать выдачу`;
3. сканирует материал или питатель;
4. нажимает `Выдать штрихкод`;
5. повторяет до выдачи всех обязательных позиций;
6. нажимает `Завершить выдачу`.

При выдаче приложение также ищет позицию по `PartNumber` внутри сканированного
штрихкода.

## Завершение заказа

После выдачи всех материалов приложение формирует отчёт и проверяет остатки.

Если остатков нет:

```text
заказ завершён
тележка свободна
можно загружать следующий заказ
```

Если остатки есть:

```text
приложение переходит в Возврат остатков
новый заказ загрузить нельзя
```

## Возврат остатков

На этапе возврата приложение показывает список оставшихся катушек.

Оператор:

1. берёт остаток из тележки;
2. сканирует штрихкод или вводит слот;
3. нажимает `Вернуть остаток`;
4. возвращает материал на склад;
5. повторяет до полного освобождения тележки.

Когда все остатки возвращены, тележка снова становится свободной.

## Админ-панель

В админ-панели можно:

```text
посмотреть модули
проверить диагностические события
сбросить тестовую тележку
```

Кнопка `Сбросить тестовую тележку` нужна только для тестов и демонстраций. В
реальной работе её нельзя нажимать без понимания последствий: она очищает
тестовые заказы, операции и состояние тележки.

## Что делать при ошибках

`Вставьте модуль`

Проверьте, что RFID-метка модуля находится рядом со считывателем.

`Заказ не загрузился`

Проверьте, что тележка свободна и в ней нет остатков.

`В BOM нет PartNumber`

Нужен другой файл спецификации или файл нужно подготовить так, чтобы в нём была
колонка `PartNumber`.

`Материал не найден в текущем заказе`

Сканированный штрихкод не совпал ни с `barcode`, ни с `PartNumber` в заказе.

`Неверный слот`

Материал был положен не в тот слот, который указан в заказе.

## Проверка через SQLite

Основная база на runtime-малине:

```bash
sqlite3 /opt/smartcart/shared/smartcart.db ".tables"
```

Последние события:

```bash
sqlite3 /opt/smartcart/shared/smartcart.db \
  "select id, ts, level, code, message from event_log order by id desc limit 30;"
```

Позиции текущего заказа:

```bash
sqlite3 /opt/smartcart/shared/smartcart.db \
  "select barcode, part_number, required_quantity, usage_priority, target_slot, status from order_items order by usage_priority, target_slot;"
```

## Web-панель наблюдения

Если web-панель включена, состояние тележки можно смотреть с ноутбука или другого
компьютера в той же сети:

```text
http://<ip-raspberry-pi>:8080
```

Панель только показывает данные и не управляет тележкой.

На странице видны:

```text
активный модуль
текущий этап маршрута
номер заказа
прогресс материалов
состояние слотов
активные катушки
последние события
```
