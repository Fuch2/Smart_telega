## 2026-04-30 — Стабилизация RFID при запуске и работе UI

Область:
- `apps/smartcart_app`
- `src/application/services`
- `src/infrastructure/hw/rfid`
- `src/presentation/qt/views`

Что изменено:
- При старте приложения неизвестная RFID-метка больше не открывает окно выбора
  типа модуля до появления главного окна.
- Если приложение запущено без приложенной RFID-метки, монитор RFID теперь может
  отреагировать на первую появившуюся метку уже во время работы UI.
- Для нескольких RC522-считывателей таймаут чтения теперь считается на каждый
  физический считыватель отдельно, а не делится между всеми настроенными
  `spidev`.
- Большие всплывающие окна этапов маршрута теперь показываются только после
  появления основного окна UI.

Зачем:
- Исправить ситуацию, когда приложение запускалось без метки, а после
  прикладывания RFID UI не переходил из состояния "Вставьте модуль".
- Убрать модальные окна, которые появлялись раньше основного окна.
- Сделать чтение RFID стабильнее при конфигурации на несколько модулей.

Проверка:
- `cmake -S . -B build/rfid-start-check`
- `cmake --build build/rfid-start-check --target smart_cart_ui smartcart_app -j 4`
- `git diff --check`
- На Raspberry Pi: запуск UI без метки, затем прикладывание RFID-метки к RC522.

## 2026-04-30 — Повторная защита старта без RFID-метки

Область:
- `apps/smartcart_app`
- `src/application/services`
- `src/presentation/qt/views`

Что изменено:
- Стартовые состояния workflow, прочитанные из БД до показа окна, больше не
  открывают большие модальные окна этапов маршрута.
- Модальные окна этапов включаются только после того, как основной `WorkerView`
  уже показан оператору.
- Если приложение стартовало без RFID-метки, а затем метка появилась, монитор
  RFID повторяет запрос на переключение модуля раз в 2.5 секунды, пока
  переключение не будет выполнено.
- При пропадании метки внутренний флаг "уже уведомляли об этом UID" очищается.
- В `AppBootstrap` добавлена защита от одновременных повторных переключений
  модуля, чтобы не открывать несколько одинаковых окон выбора типа модуля.
- Добавлен интеграционный тест на сценарий старта без ожидаемого UID и
  последующего появления RFID-метки.

Зачем:
- Исправить сценарий: UI запускается без метки, показывает "Вставьте модуль",
  но после прикладывания RFID-метки не переходит к активному модулю.
- Исправить сценарий: окно "ЗАКАЗ ЗАГРУЖЕН" появляется раньше основного окна.

Проверка:
- `cmake --build build/rfid-start-check --target smart_cart_ui smartcart_app -j 4`
- `cmake --build build/rfid-start-check --target integration_tests -j 4`
- `./build/rfid-start-check/integration_tests` — 37 тестов пройдено.
- `git diff --check`

## 2026-04-30 — Контроль исчезновения активной RFID-метки

Область:
- `src/application/services`
- `tests/integration`

Что изменено:
- `RfidModuleMonitorService` теперь переводит активный модуль в `OFFLINE`,
  если ожидаемый UID не виден дольше `rfid_offline_timeout_ms`.
- Проверка исчезновения активного UID выполняется даже тогда, когда другие
  RFID-метки всё ещё видны другими считывателями.
- Добавлен интеграционный тест на сценарий: активная метка исчезла, другая
  метка осталась видимой, активный модуль должен стать `OFFLINE`.

Зачем:
- Исправить сценарий, когда оператор убирает RFID-метку активного модуля, но UI
  остаётся на рабочем экране вместо страницы "Вставьте модуль".
- Подготовить корректную работу для тележки с несколькими RFID-считывателями и
  несколькими модулями.

Проверка:
- `cmake --build build/rfid-start-check --target smart_cart_ui smartcart_app integration_tests -j 4`
- `./build/rfid-start-check/integration_tests` — 38 тестов пройдено.
